Frozen Linux artifact -- launch on the reference machine, three graphics routes
==============================================================================

Artifact  : release/3D MASTER 2005 Beta/3D MASTER 2005 (PyInstaller, onedir)
Machine   : MX Linux 25.2 / Debian 13 trixie, kernel 6.12.90, KDE Plasma on
            Wayland, Ryzen 7 5700U + integrated AMD Radeon (amdgpu/radeonsi),
            Mesa 26.1.4, 1920x1080
Method    : launched with `env -i` -- no PATH, no PYTHON*, no virtualenv on
            the environment at all -- held for 12 s, then SIGTERM. A bundle
            that needed a system Python, or a Qt plugin it had not shipped,
            could not survive this.

1. Native session (QT_QPA_PLATFORM unset -> wayland)
   RUNNING after 12 s, exited cleanly on TERM.
   Only output: Qt's note that the scrubbed locale is not UTF-8 and it
   switched to C.UTF-8 (an artefact of `env -i`, not of the app).

2. xcb / XWayland (QT_QPA_PLATFORM=xcb)
   RUNNING after 12 s.
   NOTE: with XAUTHORITY also stripped by `env -i`, this route fails with
   "Authorization required, but no authorization protocol specified /
   qt.qpa.xcb: could not connect to display :0". That is the scrubbed
   environment, not a packaging defect: passing XAUTHORITY (which every
   real session sets) it starts normally. Recorded here because the same
   message will reach users who launch from a context without it -- e.g.
   some sudo or systemd units.
   Qt also warns that the xcb plugin needs the system's libxcb-cursor0.
   It is present on this machine (/usr/lib/x86_64-linux-gnu/libxcb-cursor.so.0)
   and is documented in SUPPORTED_PLATFORMS.md as an external requirement
   of the xcb route only; the native Wayland route does not need it.

3. Forced software GL (LIBGL_ALWAYS_SOFTWARE=1)
   RUNNING after 12 s, exited cleanly on TERM.

What this does NOT establish
----------------------------
That the app starts, stays up and shuts down cleanly on each route is
verified. Interactive usability -- that the viewport draws correctly, that
the gizmos track the cursor, that HiDPI scaling looks right -- is NOT
established by a launch test and has not been visually verified on this
machine. It is recorded as a remaining manual check.

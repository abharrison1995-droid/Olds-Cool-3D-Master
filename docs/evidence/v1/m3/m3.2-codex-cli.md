See [OpenAI's Structured Outputs schema subset](https://developers.openai.com/api/docs/guides/structured-outputs#supported-schemas).
- Added `codex_output_schema.py`, a deterministic Codex-only projection from the accepted M3.1 schema. It converts the current disjoint `oneOf` branches to `anyOf`, `const` to equivalent `enum`, string length limits to regex constraints, requires all declared fields, and closes dynamic maps. It intentionally narrows the provider's expressible recipes; M3.1's response parser, AI policy, and M2 runner remain unchanged and authoritative. Tests show a valid projected response passes the canonical parser, while texture, authority fields, and open parameter-map values are excluded.

## M3.2a focused-review remediation — 2026-10-12

The later independent source review returned **REQUEST CHANGES** with four blockers: (1) prior sentinels/event observations did not prove outside reads or model-tool network denial; (2) `_verify_local_cli` ignored unknown enabled features; (3) final-response size was checked only after the child exited; and (4) the Codex process had no OS memory limit. These findings supersede the earlier “gate satisfied” wording above. PR #16 has been returned to draft and remains unmerged.

The worktree started this remediation at `a4b5d8c2360f10d003fa15f0e524d8490811005b` on `v1/m3.2-codex-cli`, after the earlier `140445a03d3db9aed9a8fed6ed68ffe2b65f4c7b` M3.2a source/schema commit. Changes currently in the worktree reject unknown enabled feature flags, explicitly disable the installed CLI's API-key discovery/browser/daemon/proxy/unbounded-retry flags, require `shell_tool` disabled when `unified_exec` is active, monitor response-file size before CLI exit, and apply a host-owned 1 GiB process-tree memory ceiling (Linux `prlimit`; Windows Job Object). The M3.1 parser, `authorize_recipe`, and M2 runner are unchanged.

The installed executable was rechecked locally without a model call: `/usr/lib/chatgpt/resources/codex`, version `0.162.0-alpha.17.2`; `login status` reports an existing ChatGPT login. No auth file or token was opened. The current feature profile reports shell disabled and `unified_exec` enabled; the latter is accepted only with shell disabled. API-key discovery, browser/search, MCP/tool discovery, daemon autostart, network proxy/fallback, and unbounded connection retry features are explicitly disabled. Unknown enabled flags fail closed. `--no-daemon` is now a required, host-selected invocation option.

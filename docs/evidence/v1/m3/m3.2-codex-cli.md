## Live probe disposition

Two live calls were made, the maximum allowed:

1. A generic stool request plus synthetic-only probes for workspace creation, reading/writing disposable outside sentinels, reading a synthetic project note, and a browser/network fetch.
2. A plain generic stool request to isolate the first failure.

Both returned `nonzero_cli_exit` after `turn.started`, followed by `error` and `turn.failed`, in about 4.6 and 5.6 seconds. No structured response reached the M3.1 parser, and `GenerationRunner` was not started. Model identity and token usage were unavailable (`null`). The disposable outside sentinels and synthetic project note were unchanged. Since the turns failed before a result, this is **inconclusive** for workspace writes, outside reads, repository reads, model-tool network access, and hostile-config behavior. No actual repository/project file was supplied or read. No third live call was made.

The adapter requests read-only sandboxing, never approval, ephemeral execution, ignored user config/rules, and disables the installed tool features. Those requested controls are not a substitute for the missing empirical confinement probe. Do not treat this evidence as a sandbox pass.

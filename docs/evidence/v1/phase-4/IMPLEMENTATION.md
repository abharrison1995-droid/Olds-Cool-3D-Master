## Implemented behavior

`am3d.ai.checks.check_artifacts(recipe, output_dir, brief=None, generation=None, requirements=None)` audits the worker's private output after a fresh native-project load. The host-created provenance envelope is bounded and validated here, embedded in `project.am3d`, and checked after another save/reopen. A report has `ok`, `status` (`passed` or `failed`), stable check code/id, severity, nullable relative path, summary and structured details. It also has a trusted top-level `resource_limit` boolean, false by default and true only when a numeric byte/count/dimension/pixel guard fires; bounded `resource_limit_details` contain the observed value, cap, unit and fixed guard kind. Malformed data, MIME/material/geometry mismatches, and external or escaping references do not set this flag. Only a fully passing report has `ok: true`.

The checker evaluates the scene using the application's own session and geometry pipeline. It verifies finite vertices and normals, valid triangle indices, nonzero scene bounds and visible surface triangles, reports degenerate pole triangles without rejecting a model solely for them, and measures evaluated triangle/array limits. Host-owned required components must map to distinct renderable surface meshes. Caller-authored target dimensions, material assignments/colors, supported spatial predicates, rig bindings and requested animation are checked independently of model claims. Requested motion is sampled at four normalized times, including a displacement check. Expected approximations/disclosures are sourced from caller brief metadata or host warnings; the model cannot satisfy disclosure requirements by asserting them itself.

A 512x512 whole-scene preview is rendered with the existing fixed-camera software mesh rasterizer. Flat material colors use one camera and shared depth buffer, so occlusion and per-material color remain visible in the preview. Texture maps and procedural patterns are represented by their base material color and reported as a preview limitation. The decoded image is checked for bounded dimensions and nonblank/non-full-frame occupancy. Requested exports are independently parsed where supported; PNG resources are decoded and bounded. Every published artifact has a safe relative path, byte count and SHA-256 in the manifest; symlinks/junctions, collisions, unsupported files, empty files and output trees above the policy limits fail.

The native format gains an optional, bounded `generation` envelope in format 2. The reader remains compatible with formats 1 and 2 without that field; an older explicit-root-field writer naturally drops the optional metadata when saving. Validation rejects unsafe artifact paths, non-string keys, non-finite/invalid Unicode data, credential-like fields and raw HTTP payload fields. A semantic project digest excludes view-only state but covers project content. Saving compares the content to the saved provenance baseline and marks `diverged` after content edits, while preserving the original accepted recipe and run identity through Save As.

`am3d.ai.records.GenerationRecordStore` keeps private per-run candidate attempts separate from immutable completed generations. Publication re-hashes the checked manifest, stages bounded sidecars and the authoritative record, then promotes a same-volume directory by atomic rename. That rename is the cancellation/deadline commit point. Interrupted private journals are recoverable; a valid promoted record takes authority if a post-commit journal write was interrupted. History can be rebuilt from record files and includes bounded failed/cancelled/interrupted attempts. `get_record` verifies the full manifest. `create_working_copy` verifies its immutable source and copies native-project-relative texture/atlas resources without modifying history. Deletion reports child generations and requires explicit parent confirmation.

`application_identity()` records the app version and capability version. Source runs use a deterministic hash of non-test runtime `.py`/`.qss` files, the shipped `docs/recipes/recipe-v1.schema.json`, and fixed capability/prompt context labels. The value is labeled `source-code-sha256:<digest>` and is not presented as a full build-input digest. Frozen applications report `unavailable` until packaging supplies a validated `am3d/build_identity.json`.

## Independent review follow-up

The first Phase 4 independent source review was blocked by four reproducible integrity gaps. The fixes and disposition are:

1. **Checked bytes during publication:** publication now compares path, byte count, and SHA-256 tuples against the checker report, copies only those claims into a private same-volume snapshot, and verifies the snapshot again immediately before the small atomic promotion. Hashing and copying poll cancellation/deadline between bounded chunks. A changed source or staged file cannot be promoted as checked.
2. **OBJ resource boundaries:** strict checker-mode OBJ parsing rejects absolute, non-portable, escaping, linked, missing, and unsupported MTL/texture references before opening referenced sidecars. It returns every validated root-relative MTL and PNG dependency for the artifact manifest. Diagnostics contain fixed reasons without source paths or exception text. Legacy `validate_obj(path)` CLI behavior stays unchanged.
3. **Export material agreement:** requested OBJ and GLB exports are checked against the freshly reopened native scene's component/material assignments and RGB values, using the executor's deterministic safe object-name mapping. GLB external image URIs, invalid texture/image references, and embedded image ranges outside the GLB binary chunk fail. Embedded images require the writer's `image/png` MIME type and are decoded as PNG with Pillow CRC verification and bounded loading. The image count follows the 128-object recipe cap, so a bounded scene can retain one baked atlas per object; embedded payload bytes use the existing 256 MiB total-output ceiling rather than introducing a smaller GLB-only limit. Decoded pixels use the existing 64-million-pixel atlas cap, and the checker applies its existing 8192-pixel per-side PNG dimension ceiling before pixel allocation.
4. **Per-part animation binding:** every intended deforming component must have positive native weights and either its own requested-action assignment or an explicit recipe `params.skeleton` reference to an assigned master with matching bone topology. Pose fallback caused by coincidental bone names no longer satisfies the checker.
5. **Parser diagnostic boundary:** untrusted OBJ/GLB parser text is reduced to fixed issue codes and counts before entering the checker report. The public legacy validator may keep detailed CLI diagnostics; checked records never echo them.
6. **Parser read bounds:** the checker stat-preflights aggregate output bytes before opening the native project, then repeats the preflight after provenance is embedded and immediately before export parsing. Strict OBJ validation checks the main OBJ, all MTL inputs together, and referenced files against the same existing `MAX_OUTPUT_BYTES` limit before parsing sidecars; the legacy unrooted CLI path is unchanged. Regression tests patch the policy limit down to small fixture sizes and assert the parser is never called when a file or aggregate sidecar set exceeds it.

Regression coverage includes source-byte mutation after checker hashing, staging mutation before promotion, cancellation between hash chunks, external OBJ MTL/texture references, required OBJ and GLB material corruption, GLB texture bounds, and two-rig animation with both unbound and explicitly shared skeleton cases. The focused post-hardening suite before the last path-collision/cancellation additions passed **32 tests in 73.77s**. The final targeted publication/GLB checks passed **4 tests in 2.33s**; exact command output is in `review-followup-tests.txt`. The orchestrator's real worker/check/publish integration and the fresh independent re-review are pending; no Phase 4 release gate is claimed here.

The follow-up malformed-GLB sensitivity test confirmed that the legacy validator emits an injected mesh-name sentinel for a missing `POSITION` attribute, while `check_artifacts` fails the export without that sentinel in its report. The same test checks a valid requested GLB. It passed in **8.14s**; output is in `review-parser-boundary-tests.txt`.

The final embedded-image review regression passes a baked-pattern GLB and rejects wrong MIME with valid PNG bytes, valid MIME with a corrupted PNG signature, and an over-limit PNG header before pixel allocation. It also retains the external-reference and malformed-GLB diagnostic-boundary regressions. The focused command passed **3 tests in 17.31s**; output is in `review-glb-image-tests.txt`.

## Limits and pending acceptance

These checks establish file integrity, reopenability and selected structural requirements. They do not establish artistic quality, full texture/pattern fidelity, or usefulness to a person. Flat-color preview does not prove the material's texture appearance. Human review of the benchmark assets, frozen application behavior, other supported platforms, and release qualification remain pending. The source identity hash is not a binary/build dependency attestation.

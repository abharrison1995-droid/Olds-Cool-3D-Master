## Implemented behavior

`scripts/run_ai_benchmark.py` provides fixed release/discovery scopes; fake and replay modes that never construct a network transport and always report `NONQUALIFYING`; live opt-in and resume; atomic run journals; one-run reports and a two-run gate; blank human scoring exports; immutable original reviewer imports; and separately preserved disagreement resolutions. The helper module enforces fixed denominators, freezes source/fixture identities before execution and before each item, retains failures and interrupted rows, and never overwrites a terminal item. The fixture IDs and hashes are checked before a ledger is created.

Live mode requires an explicit model, a positive whole-run semantic-call ceiling, a positive completion-output reservation ceiling, a precise interactive acknowledgement of the budget limitation, and a credential from the OS store or hidden session input. The journal atomically records each semantic-call allowance and the request's full completion-output reservation before invoking the provider. A provider-reported completion count above a request reservation is retained as a failure. A configured completion-output reservation is **not a full bill ceiling**: prompt/input tokens and dollar spend cannot be bounded by this provider contract. Actual dollar cost remains null unless a provider supplies a measured value. Actual HTTP attempts remain null because the current transport contract does not expose them; `2 × semantic-call ceiling` is labeled only as a conservative upper bound from the adapter's tested one-retry limit.

Run stores are created in a unique directory beneath the per-user benchmark directory; an explicit output-parent is accepted only below that directory. The runner rejects symlink/junction paths and sets restrictive directory/file modes where the platform supports them; on Windows the store inherits the current user's LocalAppData access control.

Human templates include an item for every frozen release ID and point only to artifacts whose append-once generation receipt, store manifest, SHA-256, size, physical native load/save/reopen, decoded nonblank preview, provider/model identity, and passed whole-scene preview check verify. Receipt capture occurs only while applying the genuine returned completed outcome; report and import paths never recreate one from mutable records. Missing or failed assets stay in the denominator with null artifact references. Imports require a stable distinct reviewer ID and four integer scores from 0–2 for each of all 30 IDs. Original bytes are archived by SHA-256 with create-only semantics. Reports recompute scores and resolutions from those archived originals; derived analysis JSON is not trusted as the gate input. No visual or native-editability scores are generated by the tool.
